# Retained XO output comparison

This temporary draft compares latest/stable/rolling NAR data from successful qualifications 41145005348 (8273ea5b) and 41158639922 (e8d8bfbf). It establishes differences between those retained outputs only. It does not certify a release, verify currently served public-cache bytes, or authorize overwriting the cache. The cause remains unknown until comparison succeeds.

The read-only PR job binds exact repository/run/attempt/source/artifact identity and download digests. Product/scan GitHub attestations must match the immutable qualification workflow/source. ZIP/TAR inventories, paths, types, sizes, every transport part/archive digest, compressed NAR hash, attested root identity and decompressed NAR hash are validated before comparison. There is no rebuild or alternate-artifact fallback.

Public-cache narinfo access previously returned HTTP 403. This version makes **no request to that endpoint** and reports `publicCacheVerification.status = unavailable`, `requestedDuringThisRun = false`, with the previously observed 403 explicitly historical. Retained artifact attestations authenticate the compared hashes; this is a different claim from public-cache signature verification. All publication/cache integrity, approval, and signing gates remain unchanged. The summary has no release authority.

The GitHub token has contents/actions/attestations read access and is removed before offline NAR processing. Trusted host zstd and Nix `nar ls` read data. Package programs, fetched executables and build scripts never run. No store import, build, cache push or publication occurs. Source recipe blobs are hashed without evaluation. Actual archive-reader Nix version is recorded, not represented as the historical producer's exact toolchain.

The job has a 60-minute limit and a 45-minute comparison timeout plus 15-second kill grace. Two CPUs, 3 GiB address space and 1800 CPU seconds are allowed per inherited process, not an aggregate memory quota. Downloads are fixed at the authenticated artifact sizes (~2.65 GB each); selected NARs are at most 3 GiB, one at a time. Decompression cannot write past the expected NAR size. Listing output is capped at 256 MiB, summary at 5 MiB and samples at 2000 differing entries per profile. At least 12 GiB runner disk must be free. No automatic escalation or retry exists.

Only the bounded JSON summary is uploaded for seven days: validated relative paths, types, sizes, executable bits, SHA256 hashes, structured Python bytecode headers, derivation identities and recipe hashes. Raw file contents, NARs, scan reports, symlink targets and tool stderr stay private and are deleted in cleanup. Failures expose only fixed stages/categories and allowlisted function names/numeric lines, never raw errors, URLs or arguments.

A separate read-only scanner triage job uses the same checksum-pinned Gitleaks, protected configuration and complete incoming Git range. Its private redacted report is capped at 2 MiB and deleted; only validated rule/file/line/commit locations are printed. There is no scanner exception or baseline. A systemd service runs as the unprivileged runner UID with no new privileges, read-only system/source, private network/temp, and an enforced **3 GiB physical-memory cgroup**, zero swap, one CPU, 128 processes and 120-second runtime. The helper verifies cgroup controls before any scanner invocation. It retains 90-second scanner CPU/wall and report caps. Go virtual reservations are not mistaken for physical RAM usage. Unsupported controls fail closed; no unbounded fallback runs.

Synthetic guard/sanitizer fixtures run on hosted CI. No local tests, Nix evaluation, builds or NAR downloads occur on XPS. This draft remains temporary and requires separate review before any merge.

The structured follow-up reads only selected generated indexes, their four runtime counterparts, the index-modules generator identity, search-document JSON, documentation HTML and its main bundle as bounded data (32 MiB maximum per selected file). It emits complete-grammar module-block hashes, ordered/unordered document hashes, exact timestamped-search/asset-reference normalization hashes, and build-path/line hashes. No retained script executes and no content is emitted. Unsupported grammar is explicitly unmatched; normalization is diagnostic evidence, never a rewritten or accepted package. All previous resource, archive, provenance, hash and output limits remain enforced.
